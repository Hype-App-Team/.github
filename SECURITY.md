# Политика безопасности (Security Policy)

## Базовые правила команды

1. **Никаких секретов в Git:** токены ботов, API-ключи LLM, приватные SSH-ключи, cookies сессий (`.txt`, `.json`), файлы `.env` и локальные базы данных (`.db`, `.sqlite`, `.jsonl` с пользовательскими данными) никогда не коммитятся в репозитории.
2. **Если секрет попал в историю Git:** удаление файла новым коммитом **не считается защитой** — секрет немедленно отзывается (ротируется) у провайдера.
3. **Наименьшие привилегии в CI/CD:** все GitHub Actions в организации работают с `permissions: contents: read` по умолчанию; повышение прав задаётся точечно на уровне конкретного job.
4. **Контейнеры и ранний перехват:** образы продакшена работают от непривилегированного пользователя (`UID 10001`), с `read_only` корневой ФС и `no-new-privileges`. В каждом репозитории перед коммитом и в CI запускается проверка `scripts/check-secrets.sh`.

## Сообщение об уязвимости

Не создавайте публичные Issue с описанием уязвимостей, токенами или примерами эксплойтов. Сообщите мейнтейнерам команды напрямую в закрытом канале разработки или через GitHub Private Vulnerability Reporting в соответствующем приватном репозитории.
